💡 Why ROS 2 + XRCE-DDS instead of ROS 1 + MAVROS?

AspectOld Stack (Previous Work)Our Stack (Week 0)
OSUbuntu 20.04 FocalUbuntu 22.04 LTS Jammy
ROS VersionROS 1 Noetic (v1.16)ROS 2 Humble Hawksbill
BridgeMAVROS v2.x (MAVLink protocol)Micro-XRCE-DDS Agent v2.4.2
SimulatorGazebo Classic 11Gazebo Sim (Harmonic / Ogre2)
PX4 VersionPX4 v1.13PX4 v1.14 (Stable)
CommunicationMAVLink over serial/UDPNative DDS over UDP :8888
DeploymentDocker containersNative installation

MAVROS uses MAVLink as a translation layer. XRCE-DDS communicates directly with PX4's internal uORB message bus — faster, lower latency, and the official PX4 v1.14 recommended approach for ROS 2.

Custom Indoor World (10 × 8 × 3 m)

We built a custom SDF world file matching the inherited indoor environment specifications:

  • Dimensions: 10m × 8m × 3m
  • Walls: Wireframe visualization (cyan)
  • Physics: ODE solver, 250 Hz step rate
  • Drone Model: x500 quadcopter
  • File: indoor_10x8x3.sdf

The wireframe design allows full drone visibility while maintaining physical collision boundaries. The drone is constrained inside the room just like the real lab.

📊 Analysis

Horizontal precision is excellent (~4 cm drift), confirming stable position control. The Z-axis shows higher variance (~73 cm) which is expected during the initial takeoff transient — the drone climbs from 0m to 2.5m, and this altitude change dominates the standard deviation. Steady-state Z-hold is much tighter.

🖥️ Live Demo — Step-by-Step Commands

Three terminals needed. Run in this exact order:

Terminal 1 — Bridge
cd ~/Micro-XRCE-DDS-Agent/build
MicroXRCEAgent udp4 -p 8888

Wait for "Agent running" message

Terminal 2 — PX4 + Gazebo
cd ~/PX4-Autopilot
PX4_GZ_WORLD=indoor_10x8x3 \
make px4_sitl gz_x500

Wait for "Ready for takeoff!"

Terminal 3 — ROS 2
cd ~/px4_ros_ws
source install/setup.bash
ros2 topic list
ros2 topic hz /fmu/out/sensor_combined

Verify ~250 Hz output

Takeoff & Hover Demo

# In Terminal 2 (pxh> prompt):
commander takeoff
# Wait 30 seconds, then:
param show MPC_ACC_HOR_MAX
commander land
